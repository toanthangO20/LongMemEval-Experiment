## 7. Important Observations

### 7.1. Retrieval/context selection is the main bottleneck

The oracle gap is large:

```text
+18.3 accuracy points over A0 answerable-only
```

This supports the hypothesis:

> Better memory systems should focus on selecting the right evidence at the right granularity, not merely passing more raw sessions.

### 7.2. Multi-session and temporal reasoning are the strongest next targets

A0 errors were concentrated in multi-session and temporal reasoning. A0.5 shows these categories are also where oracle evidence helps most.

This points toward:

```text
A1: turn/chunk-level evidence retrieval
A2: evidence-table reader
A3: event/fact/preference memory writer
A4: evidence-grounded reflection
A5: temporal/event-aware retriever
```

### 7.3. Knowledge-update needs manual audit

Knowledge-update slightly decreased:

```text
A0 knowledge-update accuracy     = 0.9028
Oracle knowledge-update accuracy = 0.8889
```

This is a small difference, equivalent to roughly one additional failure. It should not be overinterpreted, but it should be audited.

Possible explanations:

```text
1. A0 retrieved extra non-gold context that helped the answer.
2. answer_session_ids may not include all useful context for update questions.
3. Oracle sessions may be too narrow for old/new comparison.
4. LLM judge/model stochasticity may explain a one-case difference.
5. Some update questions need both old evidence and new evidence.
```

Recommended audit:

```text
Audit all 8 oracle knowledge-update failures.
```

### 7.4. Oracle result is not a final method

A0.5 uses gold `answer_session_ids`. Therefore, it is an upper-bound diagnostic, not a deployable memory mechanism.

Safe wording:

> A0.5 demonstrates that a large fraction of A0 errors are recoverable if the system can identify the correct evidence sessions.

Unsafe wording:

> Our method reaches 0.917 accuracy.

## 10. Methodological Caveats

### 10.1. Oracle uses gold labels

A0.5 is not a real deployable method because it uses `answer_session_ids`.

It should be reported as:

```text
oracle upper bound
retrieval bottleneck diagnostic
```

not as:

```text
final model performance
```

### 10.2. Diagnostic artifacts are incomplete

Because A0 artifacts were unavailable, the following still need to be run:

```text
standardized retrieval metrics
failed-case taxonomy
completion length diagnostic
```

### 10.3. Same model used as reader and judge

Both reader and judge use `cx/gpt-5.2`. This is acceptable for internal experiments, but research reporting should include manual audit or a second judge setting.

### 10.4. Oracle context construction should be verified

The oracle builder uses gold sessions, but the exact text passed to the reader should be manually verified.

Recommended check:

```text
Confirm whether the reader receives:
- full sessions with user + assistant turns; or
- only user turns; or
- reconstructed context through corpus_id mapping.
```

A cleaner oracle session text format is:

```python
def session_text(session):
    return "\n".join(
        f"{turn.get('role', '')}: {turn.get('content', '')}"
        for turn in session
    )
```

## 11. Research Interpretation

A0 + A0.5 jointly support the following statement:

> A BM25 session-level baseline achieves reasonable answer accuracy, but its main weaknesses are multi-session and temporal reasoning. When oracle evidence sessions are supplied, answerable accuracy increases from 0.7340 to 0.9170, recovering 68.8% of answerable failures. This indicates that long-term memory performance is primarily bottlenecked by evidence selection and context granularity, especially for multi-session and temporal questions.

This motivates the proposed memory manager:

```text
raw sessions
→ compact evidence units
→ fact/event/preference memory
→ evidence-grounded reflection
→ temporal/event-aware retrieval
→ adaptive retrieval
```

## 13. Recommended A1 Design

A1 should not be BM25 session@10 or session@20 as the main direction.

A1 should be:

```text
BM25 turn/chunk-level evidence retrieval
+ compact evidence context
```

### 13.1. Indexing Units

| Unit | Description | Role |
|---|---|---|
| Turn | One user/assistant turn | High precision |
| Sliding chunk | 2–4 consecutive turns | Balance context and precision |
| Session fallback | Full session | Fallback when evidence is fragmented |
| Event/fact memory | Extracted memory object | Later A3 stage |

### 13.2. Evidence Metadata

Each retrieved item should preserve:

```json
{
  "evidence_id": "session_12_turn_04",
  "session_id": "session_12",
  "turn_id": 4,
  "date": "2023-05-28",
  "role": "user",
  "text": "...",
  "bm25_score": 12.4
}
```

### 13.3. Reader Context Format

Instead of raw full sessions:

```text
[Evidence 1]
date: ...
session_id: ...
turn_id: ...
role: ...
text: ...

[Evidence 2]
...
```

### 13.4. A1 Success Criteria

A1 is successful if it achieves at least one of the following:

```text
- improves answerable accuracy over A0;
- improves multi-session accuracy;
- improves temporal-reasoning accuracy;
- reduces avg prompt tokens/query significantly;
- reduces oracle gap;
- improves evidence precision while preserving recall.
```

## 14. Recommended A2 Design

A2 should be:

```text
Evidence-table reader
```

Purpose:

```text
Reduce errors in:
- aggregation;
- counting;
- summing;
- temporal filtering;
- planned vs actual event distinction;
- semantic include/exclude decisions.
```

Prompt structure:

```text
For each relevant evidence item, extract:
- evidence_id
- date
- event/entity
- value/count/amount if any
- include_or_exclude
- reason

Then answer using only included rows.
```

Expected output format:

```text
Evidence table:
| evidence_id | date | event | value | include? | reason |
|---|---|---|---:|---|---|
| s2_t4 | March 12 | charity walk | 250 | yes | user participated |
| s5_t2 | May 05 | bike-a-thon | 600 | yes | user participated |
| s4_t1 | June 01 | planned fundraiser | N/A | no | only planned |

Final answer: $850
```

A2 should be tested first on:

```text
all A0 multi-session failures
all A0 temporal-reasoning failures
all oracle remaining multi-session failures
```

A0.5 strongly validates the research direction.

It shows:

```text
1. A0 errors are largely recoverable with correct evidence.
```
